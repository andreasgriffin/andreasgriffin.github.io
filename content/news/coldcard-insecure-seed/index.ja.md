## 概要

[Coinkite は、影響を受ける COLDCARD ファームウェアのシード生成における重大な脆弱性を公表しました](https://blog.coinkite.com/coldcard-mk3-seed-generation-warning/)。[Block の技術分析](https://engineering.block.xyz/blog/predictable-rng-fallback-and-32-bit-reseed-in-coldcard-firmware)は、デバイスのハードウェア RNG の代わりに使われている予測可能なソフトウェア乱数生成器が原因だと特定し、**攻撃が活発に行われている**と警告しています。ファームウェアを更新しても、既存のシードは**修復されません**。

**影響を受ける Coinkite デバイスでシードを作成した場合は、新しいシードへ資金を移行してください。**

## 自分のデバイスは影響を受けますか?

影響を受けるかどうかは、デバイスの製造時期ではなく、**シードを生成したときにインストールされていたファームウェアのバージョン**によって決まります。

| デバイス | シード生成に使用されたファームウェア | 状態 |
|---|---|---|
| Mk1 | 公開されたすべてのファームウェア | 影響なし |
| Mk2 / Mk3 | v3.2.2 以前 | 影響なし（ハードウェア RNG を使用） |
| Mk2 / Mk3 | v4.0.0 – v4.1.9 | **脆弱** — 安全な reseed なし |
| Mk4 | 生産版 v5.0.0 以降 | **脆弱** — 約 72 ビットのエントロピーに制限 |
| Q | すべての生産版ファームウェア | **脆弱** — 約 72 ビットのエントロピーに制限 |
| Mk5 | すべての生産版ファームウェア | **脆弱** — 約 72 ビットのエントロピーに制限 |
| TAPSIGNER、OPENDIME、SATSCARD | — | 影響なし（別のコードベース） |

安全でないシードを書き出して別のウォレットにインポートしても**修復されない**ことに注意してください。シード自体が影響を受けたままです。

## 新しいシードを生成する前に修正済みファームウェアをインストールする

影響を受けるすべてのモデルとリリース系統で、修正済みファームウェアが利用可能になりました。インストールされるまでは、COLDCARD で新しいシードを生成しないでください。

| デバイス | 修正済みファームウェア |
|---|---|
| Mk2 / Mk3 | 4.2.0 以降 |
| Mk4 / Mk5（standard） | 5.6.0 以降 |
| Q（standard） | 1.5.0Q 以降 |
| Mk4 / Mk5（Edge） | 6.6.0X 以降 |
| Q（Edge） | 6.6.0QX 以降 |

Standard と Edge は別のリリース系統です。Edge を使用している場合は、自分のモデル用に修正済みの Edge リリースをインストールしてください。古い Edge 6.x が、standard リリースよりバージョン番号が高いだけでは修正済みだと判断しないでください。

## サイコロの出目やパスフレーズは保護になりますか?

- **サイコロの出目:** このバグはデバイスが生成するエントロピーのみに影響します。シード作成時に**独立した、秘密にしたサイコロの出目を 50 回以上**入力した場合（約 256 ビットのエントロピーにするには 99 回以上）、サイコロ入力だけで少なくとも 128 ビットの独立したエントロピーが確保されるため、この問題だけではそのシードは危険と見なされません。50 回未満の場合は — 何回入力したか、秘密にされていたかが不明な場合も — **移行してください**。
- **BIP-39 パスフレーズ:** 強力で一意の BIP-39 パスフレーズ（COLDCARD の PIN ではありません）は独立した防御を追加しますが、影響を受けたシードは**修復されません**。パスフレーズが短い、一般的、使い回し、推測されやすいもの、または強度に自信がない場合は、資金を危険にさらされているものとして扱い、直ちに移行してください。強力なパスフレーズを使用している場合でも、できるだけ早く新しく生成したシードへ移行してください。

## 移行チェックリスト

落ち着いて慎重に移行してください。ウォレットの移行を急ぐと、解決しようとしている問題よりも差し迫ったリスクが生じる可能性があります。

1. 代替シードを生成する前に、自分のモデルの**修正済みファームウェアをインストール**してください。希望すれば、**COLDCARD 以外の署名デバイス**で新しいシードを生成できます（[対応デバイスを参照]({{< ref "library/supported-hardware-signers" >}})）。いずれの場合も、古いシードは**再利用しない**でください。
2. 完全に新しいシードを生成し、**記録**してください。資金を入金する前に、書面のバックアップ、ウォレットのフィンガープリント、受取アドレスを検証してください。
3. Bitcoin-Safe のセットアップウィザードを使用して、新しいシードで新しい[単一署名ウォレット]({{< ref "library/setup-singlesig-wallet" >}})または[マルチシグウォレット]({{< ref "library/setup-multisig-wallet" >}})を作成してください。
4. ウィザードの受取・送金テストを完了してください。新しい署名デバイスでバックアップと受取アドレスを検証し、少量のテスト額を受け取り、新しいウォレット内の検証済みの別のアドレスへ正常に送金します。
5. 移行トランザクションに署名してブロードキャストします。
   - **単一署名ウォレット:** 手数料を高く設定して通常どおりブロードキャストし、すばやく承認されるようにします。
   - **マルチシグウォレット:** 通常どおりブロードキャストしないでください。公開メンプールで公開鍵が明らかになるためです。署名済みの生トランザクションをコピーし、[MARA Slipstream](https://slipstream.mara.com/) を通じて直接提出してください。
6. **全残高**が新しいウォレットに届いて承認されるまで、古い COLDCARD とそのバックアップを保管してください。その後にのみ、古いシードを消去してください。

Mk2/Mk3 が唯一の署名デバイスである場合は、まずファームウェア 4.2.0 以降をインストールしてください。これで代替シードが正しく生成されるため、移行を完了するために新しい COLDCARD は必要ありません。同じ手順に従い、1 台のデバイスで古いシードと新しいシードを注意深く切り替え、移行が完全に確認されるまで古いバックアップを保管してください。

## マルチシグを使用する場合

マルチシグ構成が影響を受けるデバイス**のみ**で構成されている場合、脆弱性は依然として適用されます。影響を受けない署名デバイスを少なくとも 1 つ含むクォーラムで構成を保護してください。

## 他の人の移行を手伝う場合

シード語を共有、撮影、入力するよう求めては絶対にいけません。シードは秘密に保たれ、署名デバイス自体にのみ入力される必要があります。
